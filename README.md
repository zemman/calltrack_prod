## CallTrack — мини‑CRM для обращений и инцидентов

CallTrack — небольшая CRM‑система для учёта звонков и обращений (тикетов), а также модуль **«Инциденты / События»** для регистрации и анализа инцидентов.  
Приложение написано на чистом PHP (без фреймворков) и использует MySQL/MariaDB.

Основные возможности:

- **Учёт обращений (тикетов)** с классификацией по темам, магазинам и сотрудникам.
- **Модуль инцидентов/событий** с отдельной таблицей и справочником категорий.
- **Роли и права** (операторы, администраторы).
- **Экспорт данных в CSV** (тикеты и инциденты), совместимый с Excel и кириллицей.
- **Простая установка**: один `index.php`, SQL‑схема и минимальная конфигурация.

---

## Стек технологий

- **Язык**: PHP (совместимо с PHP 5, рекомендуется PHP 7.x+).
- **Веб‑сервер**: Apache / Nginx / встроенный сервер PHP.
- **База данных**: MySQL или MariaDB.
- **Интерфейс**: классический PHP + HTML формы, без SPA‑фреймворков.

## Структура проекта

- `public/`
  - `index.php` — единая точка входа и простой роутер по параметру `page`.

  - `INCIDENTS_MODULE_README.md` — подробная документация по модулю «Инциденты / События».
  - `init_incident_categories.php` — инициализация базовых категорий инцидентов.
- `src/`
  - `bootstrap.php` — запуск сессии, подключение конфига и инициализация БД.
  - `lib/Database.php` — обёртка над PDO, инициализация соединения и CRUD‑методы.
  - `lib/Auth.php` — авторизация, хранение пользователя в сессии, проверка ролей.
  - `lib/Utils.php` — утилиты (экранирование HTML, генерация CSV и др.).
  - `lib/Audit.php` — аудит действий по тикетам (логирование изменений).
  - `controllers/` — дополнительные контроллеры (экспорт, инциденты и т.п.), логика может быть вынесена из `public/index.php`.
- `views/`
  - `layout/header.php`, `layout/footer.php` — общий шаблон, шапка/подвал и меню.
  - `login.php` — форма авторизации.
  - `tickets/` — экраны работы с обращениями:
    - `create_call.php` — создание тикета‑звонка,
    - `edit.php` — редактирование существующего тикета,
    - `list.php` — список тикетов с фильтрами и постраничным выводом.
  - `incidents/` — экраны работы с инцидентами:
    - `list.php` — список инцидентов с фильтрами,
    - `create.php` — создание инцидента,
    - `edit.php` — редактирование инцидента,
    - `categories.php` — управление справочником категорий (только админ).
  - `admin/` — административные разделы:
    - `stores.php` — управление магазинами,
    - `topic1.php`, `topic2.php` — управление тематикой обращений (темы 1 и 2 уровня),
    - `users.php` — управление пользователями и их ролями.
  - `reports/index.php` — базовый раздел отчётов (заготовка под кастомную аналитику).
- `config/`
  - `config.php` — параметры подключения к БД (DSN, логин, пароль).
- `schema.sql` — SQL‑скрипт создания всех необходимых таблиц и индексов.
- `index.html` — корневая страница/заглушка (опционально используется веб‑сервером).
- `install_*.php` — установочный скрипт (опционально) для первоначальной настройки.

## Установка и запуск

### 1. Системные требования

- PHP 5.6+ (рекомендуется 7.x и выше).
- Включённое расширение **PDO MySQL**.
- Веб‑сервер (Apache, Nginx) либо встроенный сервер PHP.
- MySQL/MariaDB с возможностью создавать базы и таблицы.

### 2. Создание базы данных

1. Создайте базу данных:

   ```sql
   CREATE DATABASE calltrack CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

2. Выполните SQL‑скрипт `schema.sql`:

   ```bash
   mysql -u <user> -p calltrack < schema.sql
   ```

   или из MySQL‑клиента:

   ```sql
   source /полный/путь/к/schema.sql;
   ```

### 3. Настройка подключения к БД

Отредактируйте `config/config.php` (при необходимости создайте на основе шаблона) и укажите параметры подключения:

```php
<?php
define('DB_DSN', 'mysql:host=localhost;dbname=calltrack;charset=utf8');
define('DB_USER', 'calltrack_user');
define('DB_PASS', 'your_strong_password_here');
```

**Важно:** реальные логин/пароль для БД не должны коммититься в репозиторий.

### 4. Настройка веб‑сервера

Рекомендуется указывать `public/` как корневой каталог сайта (**DocumentRoot**).

Примеры:

- `http://your-domain/` → `public/index.php`
- или `http://your-domain/public/` (как указано в `public/QUICK_START.md`)

Для быстрого локального запуска можно использовать встроенный сервер PHP:

```bash
cd path/to/calltrack/public
php -S localhost:8000
```

Затем открыть в браузере `http://localhost:8000`.

### 5. Инициализация модуля «Инциденты / События»

Подробно см.:

- `public/QUICK_START.md`
- `public/INCIDENTS_MODULE_README.md`

Основные шаги:

1. Убедиться, что таблицы `incidents` и `incident_categories` созданы (через `schema.sql`).
2. Инициализировать базовые категории, выполнив скрипт:

   ```bash
   cd public
   php init_incident_categories.php
   ```

   либо выполнить SQL‑вставки из `INCIDENTS_MODULE_README.md`.

3. Перейти в веб‑интерфейс (`/public/`) и убедиться, что в меню появились пункты:
   - «Инциденты»,
   - «Создать инцидент»,
   - «Категории инцидентов» (для администратора).

### 6. Создание администратора

В зависимости от версии проекта, первый администратор может создаваться:

- либо вручную через SQL‑команду `INSERT INTO users (...)`,
- либо через установочный скрипт (`install_*.php`).

Роль администратора задаётся полем `role` (например, `admin`) в таблице `users`.  
Авторизация и проверка ролей реализованы в `Auth.php`.

## Авторизация и роли

Авторизация обязательна для всех страниц, кроме `page=login`.  
Вход осуществляется через форму:

- URL: `index.php?page=login`
- Метод: `POST`
- Поля: `email`, `password`, `action=login`

Если пользователь не авторизован и пытается открыть любую страницу, кроме `login`, он будет перенаправлен на `index.php?page=login`.

### Роли пользователей

Роли обрабатываются в `Auth.php` (реальные значения зависят от реализации, типично):

- **Оператор** (`Auth::canOperate()`):
  - создаёт и редактирует тикеты;
  - создаёт и редактирует инциденты;
  - просматривает списки и отчёты;
  - может экспортировать CSV.
- **Администратор** (`Auth::isAdmin()`):
  - все возможности оператора;
  - управление пользователями;
  - управление справочниками (магазины, темы, категории инцидентов).

## Маршрутизация и основные страницы

Роутинг реализован в `public/index.php` по параметру `$_GET['page']`.  
В начале файла подключается `src/bootstrap.php`, затем обрабатываются POST‑действия и выполняется `switch ($page)` с выбором представления.

Ключевые значения `page`:

### Аутентификация

- `page=login` — форма входа.
- `page=logout` — выход, очистка сессии и редирект на страницу логина.

### Тикеты (обращения)

- `page=tickets`
  - список обращений, фильтрация и пагинация;
  - фильтры по датам, темам (`topic1`/`topic2`), магазину, сотруднику, статусу, признаку «обосновано», строке поиска по описанию/комментарию;
  - кнопки для перехода к созданию/редактированию тикета;
  - ссылка на экспорт CSV.
- `page=ticket_new_call`
  - форма создания нового тикета‑звонка;
  - выбор темы 1 и 2 уровня, магазина, статуса, признака «обосновано» и др.;
  - проверка соответствия `topic2` выбранному `topic1` на сервере.
- `page=ticket_edit&id={ID}`
  - редактирование существующего тикета;
  - аудит изменений через `Audit::logChanges()` (до/после).

### Инциденты / события

- `page=incidents`
  - список инцидентов с фильтрами:
    - даты начала,
    - категория,
    - статус (открыт/закрыт),
    - строка поиска по заголовку/описанию;
  - сортировка по статусу и дате начала;
  - доступен экспорт инцидентов в CSV (`page=export_csv&type=incidents`).
- `page=incident_new`
  - форма создания инцидента;
  - обязательные поля: заголовок, описание, дата начала, категория;
  - при сохранении автоматически выставляется `created_at`.
- `page=incident_edit&id={ID}`
  - редактирование инцидента, возможность закрытия;
  - при закрытии может автоматически выставляться дата завершения;
  - возможность изменить номер INC в сторонней системе, потенциальное влияние и текст для бота.
- `page=incident_categories` (только администратор)
  - управление справочником категорий инцидентов (`incident_categories`);
  - добавление, изменение, удаление категорий;
  - защита от удаления категорий, привязанных к существующим инцидентам.

### Админка

- `page=admin_stores` — управление магазинами (таблица `stores`).
- `page=admin_topic1` — управление темами 1 уровня (таблица `topic1`).
- `page=admin_topic2` — управление темами 2 уровня (таблица `topic2`), привязка к `topic1`.
- `page=admin_users` — управление пользователями (создание, роли, удаление).

### Отчёты

- `page=reports` — базовый экран для отчётов (может быть расширен под конкретную аналитику).

При неизвестном значении `page` выводится сообщение «Страница не найдена».

## Модуль «Инциденты / События»

Дополнительная документация по модулю находится в:

- `public/QUICK_START.md`
- `public/INCIDENTS_MODULE_README.md`

Кратко функциональность модуля:

- Регистрация инцидента с полями:
  - заголовок;
  - подробное описание;
  - статус (открыт/закрыт);
  - дата создания (заполняется автоматически);
  - дата начала и дата завершения;
  - номер INC в внешней системе;
  - потенциальное влияние;
  - категория (из справочника `incident_categories`);
  - текст оповещения для бота (опционально).
- Просмотр и фильтрация списка инцидентов (по датам, статусам, категориям и текстовому запросу).
- Редактирование инцидентов и закрытие с автоматическим заполнением даты завершения.
- Экспорт в CSV с учётом всех активных фильтров.
- Управление справочником категорий инцидентов.

Модуль реализован как **независимый функциональный блок**, не меняющий существующие таблицы и функциональность тикетной части, и использует те же стили и систему авторизации.

## Экспорт данных в CSV

Экспорт реализован в `public/index.php` в ветке `page=export_csv`.  
Поддерживаются два типа экспорта:

- `type=tickets` — экспорт обращений.
- `type=incidents` — экспорт инцидентов.

Фильтры передаются через `$_GET`, формируется SQL‑запрос с `WHERE` и параметрами, данные выбираются через `Database::fetchAll()` и конвертируются в CSV с помощью `Utils::toCsv()`.

Заголовки HTTP‑ответа:

- `Content-Type: text/csv; charset=utf-8`
- `Content-Disposition: attachment; filename=<tickets|incidents>_YYYYMMDD_HHMMSS.csv`

Файлы CSV содержат заголовки колонок на русском языке и корректно открываются в Excel.

## Безопасность

Проект учитывает базовые требования безопасности:

- **Авторизация и роли**
  - Все действия (кроме логина) проверяют авторизацию;
  - Роуты для операторов/админов дополнительно проверяют права (`Auth::canOperate()`, `Auth::isAdmin()`).
- **Валидация входных данных**
  - Проверка обязательных полей при сохранении тикетов и инцидентов;
  - Проверка согласованности справочников (например, соответствие `topic2` выбранному `topic1`).
- **Защита от XSS**
  - Все пользовательские данные при выводе в шаблонах должны проходить через `Utils::h()`.
- **Защита от SQL‑инъекций**
  - Используются подготовленные запросы и параметризованные выражения в `Database::execute()` и др.
- **Конфигурация**
  - Параметры доступа к БД вынесены в `config/config.php` и не должны храниться в открытом виде в системе контроля версий.

## Расширение и доработка

Проект спроектирован так, чтобы его можно было легко расширять:

- **Новые страницы**
  - Добавьте новую ветку в `switch ($page)` в `public/index.php`;
  - Создайте соответствующий шаблон в `views/` (с использованием `layout/header.php` и `layout/footer.php`).
- **Новые сущности**
  - Добавьте таблицу и индексы в `schema.sql`;
  - Реализуйте логику в `src/lib/` и/или `src/controllers/`;
  - Добавьте экран(ы) в `views/` и пункт(ы) в меню.
- **Новые отчёты и форматы экспорта**
  - Расширьте логику `page=export_csv` (новые значения `type`) или добавьте отдельные контроллеры/роуты;
  - Используйте `Utils::toCsv()` либо добавьте собственные функции экспорта.
